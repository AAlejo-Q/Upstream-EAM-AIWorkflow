Story Authoring Workflow v2.0

Restructured to consume dev team analysis before independent work, classify validations by tier, and close the feedback loop on story–spec gaps.

📅 2026-06-03 👤 Aaron Alejo · Asher Maddox 📂 AAlejo-Q/Upstream-EAM-AIWorkflow

Process Flowchart

Read top-to-bottom. Diamonds are decisions, amber-bordered bars are approval gates, dashed purple box is the feedback return loop. changed = modified from v1.1. new = added in v2.0.

Phase 1 — Analysis

1.1 Identify Screen

Confirm screen ID, parent Feature ID, migration pattern (Lift & Shift / Redesign / Combine).

1.2 Review Existing Context

Load eam-project-instructions.md, Effort-Priority-Matrix.md (authoritative), ADO parent Feature.

1.3 Check Dev Team Artifacts new

Query Quorum-Enterprise/Quorum.Upstream.AITools repo for: Analysis files (5 docs), Screen-Spec, ADO Story Analysis gap report.

Dev artifacts found?

Analysis + Screen-Spec present for this screen?

✓ Yes — Fast Path

Consume analysis + spec as baseline. Skip independent source reads. Go to 1.5.

✗ No — Full Analysis

Read full QFrm{ID}.cs, all BR method bodies, two-sided verification. Go to 1.5.

1.4 Source Analysis (if needed)

Full or targeted — InitializeBusinessRules, InitializeData, InitializeControlState, context methods. Two-sided contract verification for navigation, audit, delete rules.

↓ both paths converge

1.5 Metadata Queries new

Always run via quorum-metadata-dev MCP: grid config (QARCH_CNFG_GRIDCTRL_NET), grid columns (QARCH_CNFG_GRIDCTRL_COL_NET), code tables, pick lists, SQL key inventory.

1.6 Classify Rules by Tier new

Assign every BR to Tier 1 (in-memory), 2 (DB-lookup), 3 (commit-time), or 4 (side-effects). Tier 4 → routed to special stories, excluded from -02. Resolve RES_MSG_* strings to canonical English.

1.7 Uncertainty & Escalation

Admit unknowns explicitly. Exhaust broader search, base class check, dev team Open Questions before marking as SME question.

1.8 Translate to PO Voice

Convert to business language. Include tier classification, canonical error text, artifact source references.

Phase 2 — Planning

2.1 Select Decomposition changed

Map to Universal Story Sequence. Show dev artifacts consumed, tier counts (T1/T2/T3), Tier 4 rules → special stories.

2.2 Evidence Check

Every story beyond -01/-02 must trace to a confirmed Phase 1 artifact. Unconfirmed → Open SME Question.

2.3 Present Plan & Risks

Story map, tier distribution, gap report contradictions, dependencies, complex BRs, cross-screen impacts.

⛔ Gate — Await PO/BA Approval

Do not proceed to story generation until explicit approval.

Phase 3 — Story Generation

3.1 Load Templates

Read eam-story-core.md (mandatory) and eam-ac-library.md before writing any HTML.

3.2 Draft Stories changed

-01: Foundation/CRUD — §16 nav, §1+§4 query, §26 record view, §3+§21-§25 pagination.
-02: Validations — <!-- Tier N --> annotations + canonical RES_MSG_* error text. Tier 4 excluded.
-03+: Special — Tier 4 rules, Notes, batch, navigation.
-QA: Testing. Security: Satellite → Feature 1786977.

3.3 PO Voice Scan

Strip class/table/procedure/method names. Replace with observable business outcomes.

Phase 4 — Review & Refinement

4.1 Display, Explain, Iterate

Present full story map. Explain consolidation. Flag caveats. Iterate on feedback.

Phase 4.5 — Pre-Creation Validation Gate

4.5a Critical 5 Checks

① <h2>User Story</h2> + "As a..." ② No security in numbered stories ③ Area path from live sibling ④ No SP in HTML ⑤ §21-§25 AC on grid stories

4.5b Full Validation Checklist

Template structure, Given/When/Then, paired +/- ACs, tags, parent Feature, tier annotations, Tier 4 exclusion.

4.5c Screen-Spec Alignment new

Cross-check stories against Screen-Spec sections: business rules, special behaviors, grid layout, Notes, navigation. Log and fix gaps.

All checks pass?

Critical 5 + checklist + spec alignment

✗ Fail

Fix violations. Return to 4.5a. No known failures proceed.

✓ Pass

All checks satisfied → Phase 5.

Phase 5 — ADO Creation

⛔ Gate — Explicit Approval Required

"Confirmed", "go ahead", "create them", "approved". Silence ≠ approval.

5.1 Create with Parent Link

wit_add_child_work_items — title + description + parent. Numbered → functional Feature. Security → 1786977.

5.2 Batch Update Fields

ACs, tags (eam-phase-*), AssignedTo. No SP. No Iteration Path.

5.3 Successor Links & Verify

Chain: -01 → -02 → … → -QA. Security excluded. Confirm parent, chain, tags. Log IDs.

Feedback Loop

↩ Gap Report Consumption new

When dev team runs Analyze-ado-stories: read gap report → classify each finding as contradiction (blocks their pipeline), spec-only (may need story), story-only (may be over-specifying), or open question → draft amendment plan → await approval → update ADO.

↩ returns to Phase 4 for amendments

Gaps Addressed

Four cross-functional alignment gaps identified between Products and Dev. Each maps to specific v2.0 changes.

Gap 1

Duplicate Analysis

Both teams independently analyze the same screens. Dev queries 7+ metadata tables, runs 14+ code searches, produces 5 structured docs.

→ Phase 1.3 + Phase 1.5
Gap 2

Parallel Artifacts

Screen-Spec and ADO stories are independently authored with different structure and detail level.

→ Phase 4.5c (spec alignment)
Gap 3

One-Way Feedback

Dev's gap report never returns to Products. Contradictions block their Audit gate but we never see them.

→ Feedback Loop
Gap 4

Tier Misalignment

Dev classifies rules into 4 tiers. Our stories don't. Dev's Claude re-derives — sometimes incorrectly.

→ Phase 1.6 + Phase 3.2
